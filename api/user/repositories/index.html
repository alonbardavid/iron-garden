Repositories

Reading a repository takes Read, with any key. Changing its settings and members takes Admin and a person: an agent key gets 403, whatever its level. Rules take Admin, from a person or an agent.

The repository object

Section titled “The repository object”
FieldTypeDescription
idstringStarts with REPO_
namestringThe name in its URLs
descriptionstring | null
defaultBranchstring
levelread | write | adminThe caller’s level on it
cloneUrlstringhttps://<instance>/<name>.git
createdAtnumber
updatedAtnumber

GET /api/repositories

Section titled “GET /api/repositories”

Every repository the caller can read, each with stats: openPullRequests, activeSessions, members, and github, { owner, repo } or null.

GET /api/repositories/{name}

Section titled “GET /api/repositories/{name}”

The repository, with head: the default branch’s commit, or null when it has none or git hosting is off.

GET /api/repositories/{name}/contents

Section titled “GET /api/repositories/{name}/contents”

What a path names at a branch or commit.

QueryTypeRequiredDescription
refstringNoA branch or commit; the default branch when left out
pathstringNoThe path; the root when empty

A directory answers { "kind": "directory", "entries": [{ name, type }] }, directories first, where type is directory, file, symlink or submodule. A file answers { "kind": "file", "file": {...} }, with file as on a pull request’s file.

GET /api/repositories/{name}/files

Section titled “GET /api/repositories/{name}/files”

Every file path at ref (a branch or commit; the default branch when left out): { "paths": string[], "truncated": boolean }. A very large tree is cut short, with truncated true.

GET /api/repositories/{name}/branches

Section titled “GET /api/repositories/{name}/branches”

Every branch, the default one first: { name, commit, isDefault }[].

GET /api/repositories/{name}/commits

Section titled “GET /api/repositories/{name}/commits”

A page of a branch’s or commit’s history, newest first.

QueryTypeRequiredDescription
refstringNoA branch or commit; the default branch when left out
offsetnumberNoCommits to skip; 0 by default
limitnumberNo1 to 100; 30 by default

The response is { "commits": [{ hash, message, author, committedAt, parents }], "hasMore": boolean }.

GET /api/repositories/{name}/commits/{hash}

Section titled “GET /api/repositories/{name}/commits/{hash}”

One commit, by its full hash, and the files it changes against its first parent: { commit, files }, with files as { path, change, oldLines, newLines }[].

GET /api/repositories/{name}/commits/{hash}/file

Section titled “GET /api/repositories/{name}/commits/{hash}/file”

A file the commit changes, before and after it. It takes path as a query parameter and answers like a pull request’s file.

PATCH /api/repositories/{name}

Section titled “PATCH /api/repositories/{name}”

Changes the repository’s settings. People with Admin only.

FieldTypeRequiredDescription
newNamestringNoA new name, in the same shape as an agent’s
descriptionstring | nullNoUp to 500 characters
defaultBranchstringNoA valid git branch name

The response is the repository. A name already taken answers 409.

DELETE /api/repositories/{name}

Section titled “DELETE /api/repositories/{name}”

Deletes the repository, its session repositories and everything recorded about it. People with Admin only. It answers { "ok": true }.

Members

Section titled “Members”

GET /api/repositories/{name}/members

Section titled “GET /api/repositories/{name}/members”
FieldTypeDescription
membersarray{ user: { id, name, email, username, role, active }, level }
agentsarray{ agentId, agentName, ownerUserId, granted, effective }: the level each agent was granted, and the one it has, never above its owner’s

PUT /api/repositories/{name}/members/{userId}

Section titled “PUT /api/repositories/{name}/members/{userId}”

Adds a person, or changes their level. People with Admin only.

FieldTypeRequiredDescription
levelstringYesread, write or admin

It answers { "ok": true }. Take user ids from GET /api/users.

DELETE /api/repositories/{name}/members/{userId}

Section titled “DELETE /api/repositories/{name}/members/{userId}”

Removes a person. People with Admin only. Removing or lowering the last admin is refused.

Rules

Section titled “Rules”

A pull request copies the rules when it is opened or refreshed. A change to a rule applies from the next revision. See Rules for what each action does.

FieldTypeDescription
idstring
namestring
matchobjectSee A rule’s input
actionstring
reviewers{ id, name }[]For require-review
workflow{ id, path, name } | nullFor run-workflow
enabledboolean
lastMatched{ number, at } | nullThe latest pull request it matched
recent{ matched, of }How many of the repository’s last ten pull requests it matched
createdAtnumber
updatedAtnumber

GET /api/repositories/{name}/rules

Section titled “GET /api/repositories/{name}/rules”

Every rule. Read.

GET /api/repositories/{name}/rules/{id}

Section titled “GET /api/repositories/{name}/rules/{id}”

One rule. Read.

POST /api/repositories/{name}/rules

Section titled “POST /api/repositories/{name}/rules”

Creates a rule, sent as { "rule": {...} }. Admin.

PUT /api/repositories/{name}/rules/{id}

Section titled “PUT /api/repositories/{name}/rules/{id}”

Replaces a rule, sent as { "rule": {...} }. Admin.

A rule’s input

Section titled “A rule’s input”
FieldTypeRequiredDescription
namestringYesUp to 100 characters
matchobjectYesOne of the three below
actionstringYesauto-accept, high-impact, require-review, run-workflow or mark-exclusive
reviewersstring[]NoUp to 20 user ids, for require-review
workflow{ id, path, name } | nullNoA GitHub Actions workflow, for run-workflow
enabledbooleanNotrue by default
match.kindOther fields
filessyntax, glob or regex; patterns, 1 to 50, each up to 300 characters
structureconstructs, one or both of imports and comments; paths, up to 50 patterns limiting where it looks
promptprompt, what to look for in words, up to 5,000 characters; paths, up to 50 patterns

A mark-exclusive rule takes only files.

PUT /api/repositories/{name}/rules/{id}/enabled

Section titled “PUT /api/repositories/{name}/rules/{id}/enabled”

Turns a rule on or off: { "enabled": boolean }. Admin. The response is the rule.

DELETE /api/repositories/{name}/rules/{id}

Section titled “DELETE /api/repositories/{name}/rules/{id}”

Deletes a rule. Admin. It answers { "ok": true }.

POST /api/repositories/{name}/rules/copy

Section titled “POST /api/repositories/{name}/rules/copy”

Copies rules from another repository into this one. Admin here, and Read on the other.

FieldTypeRequiredDescription
fromstringYesThe other repository’s name
idsstring[]Yes1 to 100 rule ids there

The response is { "rules": [...], "dropped": string[] }. dropped names the run-workflow rules left behind because this repository has no workflow at the same path.
