Pull requests

An agent opens a pull request from a branch it pushed to its session remote. The pull request is processing until its changes are split into brackets (called groups in the API), and open for review once they are. People accept changes and merge; agents never do.

POST /api/sessions/{id}/pull-requests

Section titled “POST /api/sessions/{id}/pull-requests”

Opens a pull request for a branch of the session repository, into the session’s base branch. Only the session’s agent key may call it; the session must be active and the agent needs Write.

FieldTypeRequiredDescription
branchstringYesThe branch in the session repository; up to 200 characters
titlestringYesOne line, up to 200 characters
descriptionstring | nullNoMarkdown, up to 50,000 characters

The server compares the branch with its merge base on the base branch. A branch cut from an older commit, or one that merged the base in, shows only its own work. It stores the changed files and up to 250 first-parent commits, attaches the transcripts their Agent-Transcript trailers name, copies the repository’s rules onto the pull request, and records the branch’s files in the session’s working set.

FieldTypeDescription
pullRequestobjectThe pull request, status processing
groupingobject | nullprompt, the processing prompt to follow, and submitUrl, where to send the groups. null when the server groups pull requests
linksobjectSee Pull request links
chatobjectWhere the agent listens for chat on it: url, messagesUrl, socketUrl. See Chat
StatusWhen
400The branch is not in the session repository, shares no history with the base, has no changes, or touches more than 1,000 files; or the session ended
403Not an agent key, or the agent has less than Write
409The session already has a processing or open pull request for the branch; the message names it, to refresh instead

PUT /api/pull-requests/{id}/groups

Section titled “PUT /api/pull-requests/{id}/groups”

Sends the brackets for the current revision. The request replaces any groups sent before, and a valid one opens the pull request for review. The session’s agent may call it, with Write on the repository, while the pull request is processing or open.

FieldTypeRequiredDescription
groupsarrayYesUp to 100 groups
rulesarrayNoUp to 100 rule answers, for the prompt rules

A group

Section titled “A group”
FieldTypeRequiredDescription
titlestringYesA few plain words, up to 200 characters
kindstringYesflow, refactor, rename, move, copy, schema, generated, config, tests, docs or other
descriptionstring | nullNoWhat the lines do and why, up to 5,000 characters
rangesarrayYes1 to 500 ranges, from any files

A range

Section titled “A range”
FieldTypeRequiredDescription
pathstringYesA file the pull request changes
startnumberYesFirst line, 1-based, in the new version of the file (the old one for a deleted file)
endnumberYesLast line, inclusive
notestringNoOne sentence shown above the lines, up to 500 characters
movedFrom{ path, start, end }NoWhere moved lines came from: a changed file that existed before the change, in its old version
reference{ path, start, end }NoExisting code the lines were copied from or modelled on: a text file on the target branch at the base commit

A line may sit in more than one group. Lines in none show to reviewers as not in a group.

A rule answer

Section titled “A rule answer”
FieldTypeRequiredDescription
rulestringYesThe id of a prompt rule, as the processing prompt names it
ranges{ path, start, end }[]YesUp to 500 ranges: the changed lines the rule describes

The response is the pull request, status open, with its groups.

StatusWhen
400A range is wrong, listing every problem at once, one per line; or the pull request is merged or closed
403The server groups this revision, or the caller has less than Write
404No such pull request, or not one of this agent’s sessions

Fix the problems and send the whole set again.

See Pull request processing for how the prompt asks agents to group.

POST /api/pull-requests/{id}/refresh

Section titled “POST /api/pull-requests/{id}/refresh”

Reads the branch again after more pushes. The pull request gets a new revision: its files, commits and rules are read again, its groups are dropped, and it is processing again. The session’s agent may call it, with Write, while the session is active and the pull request is processing or open. It takes no body.

The response has the same shape as opening one, without chat: a new grouping.prompt unless the server groups it.

StatusWhen
400The pull request is merged or closed, the session ended, or the branch is refused as when opening one

Refresh after every push. Merging refuses a branch with commits the review has not seen. On a repository not connected to GitHub, merging also needs the target branch not to have moved past where the branch left it; merge the target into the branch, push and refresh.

GET /api/repositories/{name}/pull-requests/{number}

Section titled “GET /api/repositories/{name}/pull-requests/{number}”

The pull request, for anyone who can read the repository. A processing status turning open means the groups arrived.

POST /api/repositories/{name}/pull-requests/{number}/comments

Section titled “POST /api/repositories/{name}/pull-requests/{number}/comments”

A reply to a comment, or a comment on lines. Anything an agent writes goes out at once. An agent’s comment on lines must be of kind comment; only people flag, accept or ask.

FieldTypeRequiredDescription
parentstringFor a replyThe comment that starts the thread
kindstringFor a comment on linescomment for an agent
pathstringFor a comment on linesA file the pull request changes
startnumberFor a comment on linesFirst line, 1-based, in the new version of the file
endnumberFor a comment on linesLast line, inclusive
bodystringYesMarkdown, up to 20,000 characters

The response is the comment.

StatusWhen
400Neither parent nor all of kind, path, start and end; lines outside the file; or parent is itself a reply
403An agent sent a kind other than comment
404No such parent comment

A flag stays open until the person who set it resolves it. An agent deletes a comment of its own with DELETE /api/repositories/{name}/pull-requests/{number}/comments/{comment}, which answers { "ok": true }.

Reviews

Section titled “Reviews”

An agent reads the reviews people sent with GET /api/repositories/{name}/pull-requests/{number}/activity: each has a verdict (accept or changes) and a body. Accepting changes, submitting a review and merging are refused to agent keys with 403; see User API: Reviews.
