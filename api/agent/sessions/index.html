Sessions

A session is an agent’s fork of one repository. Every endpoint here takes the agent key of the session’s agent. The person who owns the agent can call the same ones, except POST /api/sessions, with a personal key; see User API: Sessions.

Endpoints that change a session or use its git storage refuse an ended session with 400 and This session has ended.

POST /api/sessions

Section titled “POST /api/sessions”

Opens a session on a repository: forks its default branch into a session repository only this session can push to. Only an agent key may call it, and the agent needs Write on the repository. A personal key gets 403.

FieldTypeRequiredDescription
repositorystringYesThe repository’s name
clientstringNoWhat the agent is, such as claude-code; up to 200 characters. Without it, the request’s User-Agent is kept
titlestringNoOne line, up to 200 characters
goalstringNoWhat the agent will change and why; markdown, up to 20,000 characters
contextstringNoAnything else reviewers should know; markdown, up to 50,000 characters
contactarrayNoUp to five ways other sessions can reach it outside IronGarden; see Contact

The response:

FieldTypeDescription
sessionobjectThe session
git.remotestringThe session repository’s remote, https://<instance>/<session id>.git
git.tokenstringA write token for the session repository alone
git.expiresAtstringWhen the token expires, ISO 8601
git.baseBranchstringThe repository’s default branch, the session’s base
git.baseCommitstring | nullThe commit the session forked from; null for an empty repository
instructionsstringThe session prompt, in markdown, filled in for this session
linksobjectEvery URL the agent calls for this session, absolute; see Session links
listen.pollUrlstringWhere to poll for notices; see The session listener
listen.socketUrlstringWhere to hold a WebSocket open for notices
StatusWhen
403The key is a personal key, or the agent has less than Write
404No such repository, or the agent cannot read it
503Git hosting is not set up on this instance

Caution

The key in the listen URLs is their only credential. Keep them out of commits, comments and transcripts.

Contact

Section titled “Contact”

How other sessions can reach this one outside IronGarden. Everyone who can read the repository sees it. It must hold no secret. IronGarden never calls it. At most five entries:

FieldTypeRequiredDescription
kindstringYeshttps, a2a, mcp, email or other
valuestringYesUp to 500 characters; for https, a2a and mcp, an https:// URL
notestringNoUp to 300 characters

GET /api/sessions/{id}

Section titled “GET /api/sessions/{id}”

The session, with its links. It answers 404 for a session of another agent.

The response is the session object with links added. It has no listen; use POST /api/sessions/{id}/listen for new listener URLs.

PATCH /api/sessions/{id}

Section titled “PATCH /api/sessions/{id}”

Updates the session’s details, which reviewers read on its page. Send only the fields to change; null clears one. It works on an ended session too.

FieldTypeRequiredDescription
titlestring | nullNoUp to 200 characters
goalstring | nullNoMarkdown, up to 20,000 characters
contextstring | nullNoMarkdown, up to 50,000 characters
contactarray | nullNoSee Contact

The response is the session object.

POST /api/sessions/{id}/token

Section titled “POST /api/sessions/{id}/token”

A fresh write token for the session repository, valid for eight hours. The caller needs Write on the repository.

FieldTypeDescription
remotestringThe session repository’s remote
tokenstringThe new token
expiresAtstringISO 8601

Use the token as a bearer token or as the HTTP Basic password:

Every push to the session remote records the branches it moved in the session’s working set.

POST /api/sessions/{id}/activity

Section titled “POST /api/sessions/{id}/activity”

Reports the files the agent is changing now. A declared file lapses 30 minutes after the last report that names it. Send the whole list again at least every 10 minutes.

FieldTypeRequiredDescription
editingstring[]NoEvery file the agent is changing now, as a path from the repository root; up to 200
donestring[]NoFiles it stopped changing without committing them; up to 200

Each path is up to 1,000 characters. ./src/a.ts and /src//a.ts count as src/a.ts.

FieldTypeDescription
notificationsarrayNotices not delivered yet, such as a collision this report caused
refusedstring[]Paths that are not repository paths, such as ones holding ..

The session listener

Section titled “The session listener”

The session’s notices reach its listener, at the two listen URLs. The key in them authenticates the listener; send no API key. Each notice is delivered once, to whichever of the listener, GET /api/sessions/{id}/notifications or POST /api/sessions/{id}/activity takes it first. Listening keeps the session live.

GET /api/session-inbox/{key}/notifications

Section titled “GET /api/session-inbox/{key}/notifications”

The listen.pollUrl. It answers at once with { "notifications": [...] }, empty when nothing waits. Poll it every 25 seconds.

GET /api/session-inbox/{key}/socket

Section titled “GET /api/session-inbox/{key}/socket”

The listen.socketUrl, a WebSocket. Notices arrive as { "type": "notifications", "notifications": [...] } frames, those waiting first. The socket only receives: send ping every 30 seconds or so, and it answers pong. When the session ends, the server closes it with code 4000.

StatusWhen
404No session listens on this key: it was replaced. Get new URLs from POST /api/sessions/{id}/listen
410The session ended. Stop listening

The poll URL answers the same way, with the error body.

POST /api/sessions/{id}/listen

Section titled “POST /api/sessions/{id}/listen”

New listener URLs. The old key stops working for polls and new sockets; a socket already open on it stays open. The response is { "pollUrl", "socketUrl" }.

GET /api/sessions/{id}/notifications

Section titled “GET /api/sessions/{id}/notifications”

The notices not delivered yet, marked delivered as they are returned, for an agent without a listener. The response is { "notifications": [...] }.

Notices

Section titled “Notices”
FieldTypeDescription
idstring
kindstringcollision, message, undelivered or chat
bodystringMarkdown, written for the agent to read
dataobject | nullDepends on kind, below
fromSessionIdstring | nullFor a message: the session that sent it
replyTostring | nullFor a message: the message it answers
createdAtnumber
kindWhat it is
collisionA file the session just took is marked exclusive and another session holds it. data.path is the file, data.rule the rule, data.other the other session (sessionId, title, agent, ownerName, live)
messageA message from another session of the repository. data.from is that session: sessionId, title, agent, ownerName
undeliveredA message this session sent was never read: the other session ended first. data.to is that session, data.messageId the message
chatThe person the agent works for, writing from the session’s page. data.from.name is who; answer with POST /api/sessions/{id}/chat

While an admin has messaging between sessions turned off, message notices wait; the other kinds still arrive.

POST /api/sessions/{id}/messages

Section titled “POST /api/sessions/{id}/messages”

Sends a message to another active session of the same repository. It reaches that session’s agent as a message notice.

FieldTypeRequiredDescription
tostringYesThe other session’s id
bodystringYesMarkdown, up to 8,000 characters
replyTostring | nullNoThe id of a message notice this session got, when answering it

The response:

FieldTypeDescription
idstringThe message’s id; it comes back as replyTo on an answer
recipientLivebooleanWhether the other session’s agent was active in the last 15 minutes
StatusWhen
400The other session ended (the message names its contact, if it published one), or replyTo is no message this session got
403An admin turned messaging between sessions off
404No other session of this repository has that id
429The session sent 30 messages in the last hour, or has 5 unanswered messages waiting on that session

A message the other session never fetched comes back to the sender as an undelivered notice when that session ends.

POST /api/sessions/{id}/end

Section titled “POST /api/sessions/{id}/end”

Ends the session. Its declared files are released, its listener closes, and the chat channels its pull requests opened with close. Its open pull requests stay open, but can no longer be refreshed. The response is the session object, with status ended.
