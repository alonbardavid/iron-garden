Working with edge-stack

IronGarden is built on edge-stack, an opinionated foundation for products on Cloudflare and GitHub. It sets the shape of the repository, the conventions, and the development workflow of previews, staging and end-to-end tests. This page is a map of where things live, and where a customization goes.

What edge-stack includes

Section titled “What edge-stack includes”
  • One TypeScript monorepo, managed with pnpm and Turbo.
  • One Cloudflare Worker that serves the API (Hono), the git endpoints, the web app (React with Mantine) and these docs.
  • A contract-first API with oRPC: every procedure is declared once and shared by the server and the web app.
  • D1 with numbered SQL migrations, and Drizzle for queries.
  • better-auth for sign-in, users, admins and API keys.
  • react-email templates for transactional email.
  • GitHub Actions for per-branch previews, staging, production and end-to-end tests. See Developing with staging.

The layout

Section titled “The layout”

The domain libraries decide who may do what. Routes and screens stay thin: they pass the signed-in user, or the agent acting for its owner, to a library and show the answer.

Where a change goes

Section titled “Where a change goes”
You want to addWhere
A page in the web appA screen under apps/frontend/src/screens/, and its route in apps/frontend/src/App.tsx. Account and admin pages also get a link in the side navigation.
An API procedureDeclare it in libs/contract/src/ first, then implement it in apps/backend/src/routes/, calling a domain library for the logic and the access decision. Admin-only procedures go on the admin implementer.
A database tableThe table in libs/db-models, and a new numbered SQL file in migrations/. Apply it locally with pnpm db:migrate.
An emailA react-email template beside the library that sends it, sent through the email service. Preview templates with pnpm email:dev. See emails.
An optional featureAsk libs/capabilities whether the deploy has what it needs, and keep working, degraded, without it.
A docs pageA Markdown file in apps/docs/src/content/docs/, listed in the sidebar in apps/docs/astro.config.mjs.
A new product namePRODUCT_DISPLAY_NAME in libs/contract/src/constants.ts. The app, emails, prompts and docs read it. Cloudflare resource names are separate (see below).

Caution

Changing the display name is safe. Renaming the Cloudflare resources (iron-garden, its databases and Artifacts namespaces) is a migration of live data; follow Renaming the instance in the contributor docs.

Conventions

Section titled “Conventions”

The repository’s rules are written for both people and coding agents:

  • CLAUDE.md: the architecture boundaries and traps. Coding agents load it in every session.
  • .claude/commands/check-conventions.md: the code-review rules.
  • Lint, the type-checker and the tests enforce the rest. pnpm lint, pnpm type-check, pnpm test:unit and pnpm test run what the E2E Tests workflow runs.

Contributor docs

Section titled “Contributor docs”

The code itself is documented in the repository:

  • Architecture: the layout, the API contract, identity and keys, git hosting, sessions, GitHub.
  • Development: local development, the build, the local database.
  • Deployment: previews, staging and production.
  • Tests: traps in the end-to-end suite.

To keep your copy current as both upstream and edge-stack move on, see Pulling from origin.
