# Monorepo

Date: 2026-10-09

## Decision

The app lives in a single monorepo.

To limit conflicts now and keep a future split cheap, modules keep strict boundaries
(especially frontend/backend), enforced by ESLint rules as much as possible.

## Why

The app is meant to be easy to deploy and manage. One repo lets everything run from one
place — e2e tests, deployments, and AI agents — which greatly simplifies workflows.

## Trade-offs

Multiple repos / micro-services mainly pay off through organizational separation. If enough
people start clashing on the project, reconsider splitting into separate repos.
