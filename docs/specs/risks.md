# Risks, limits and TODOs

The biggest risk is the git engine itself, so Phases 0–2 prove it before any forge UI is built.

| Risk                                                                                                                                                                 | Impact                                                              | Mitigation                                                                                                                                                                                                              |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Pack parsing needs per-object compressed lengths, which the platform `DecompressionStream` does not report                                                           | Push indexing cannot work without it                                | Phase 0 Spike B picks an inflater that reports consumed bytes                                                                                                                                                           |
| Worker memory (128 MB) and CPU limits on large pushes and clones                                                                                                     | Big repos fail or time out                                          | Stream everything; index in chunks across DO alarms; v1 targets repos up to about 1 GB and pushes up to the plan's request-body limit (100 MB on Free)                                                                  |
| Deploy button does not handle the edge-stack monorepo layout                                                                                                         | One-click deploy breaks                                             | Phase 0 Spike A; fall back to a prebuilt root worker entry if needed                                                                                                                                                    |
| Hand-written protocol has subtle incompatibilities with some git versions                                                                                            | Clones or pushes fail for some users                                | Interop tests run real git on at least two versions; v0 fallback alongside v2                                                                                                                                           |
| Server-side merge correctness                                                                                                                                        | Wrong merge results                                                 | Only clean merges server-side; fixture tests against real `git merge-tree` output                                                                                                                                       |
| Workers AI quality is weaker than frontier models                                                                                                                    | Poor groups, classifications or impact checks                       | Optional external key; AI can flag and require but only auto-review where a rule opts in                                                                                                                                |
| Generated session secret is stored in D1, so anyone with D1 access can forge sessions                                                                                | Session forgery by someone with account access                      | D1 access already implies full control of the instance; operators can override with a Worker secret                                                                                                                     |
| Public repo invites attacks on CI and on deployed instances                                                                                                          | Leaked secrets, hijacked instances                                  | Security rules in [guidelines.md](./guidelines.md#3-secure-without-obscurity); `SECURITY.md`; pinned actions; no secrets for fork PRs                                                                                   |
| Workers Previews are new; preview isolation for D1 and R2 is ours to manage                                                                                          | Previews share or leak data, or teardown misses resources           | Per-branch D1 and R2 prefix named from the branch; teardown deletes all three; weekly orphan sweep (edge-stack convention)                                                                                              |
| Remote tests on real Cloudflare are slower and can flake on network                                                                                                  | Slow or noisy CI                                                    | Remote suites run after deploy, in parallel with review; a failure attaches traces; re-run only to confirm infrastructure faults, never to hide a real failure                                                          |
| Line identity across revisions is wrong (marks kept on changed code, or lost on unchanged code)                                                                      | Reviewers trust a mark that no longer covers the code, or redo work | Conservative: any doubt resets the mark; fixture-driven tests for every row of the carry-over table; the UI shows why a mark was kept                                                                                   |
| Multi-repo merge is not one transaction                                                                                                                              | A failure mid-merge leaves repos inconsistent                       | Pre-check all sources, merge in fixed order, compare-and-swap rollback; the change request records every step                                                                                                           |
| Review rules weaken review (a rule auto-reviews too much, or a change edits its own rules)                                                                           | Unreviewed risky code merges                                        | Rules read from the target branch; requirements beat auto-review; AI auto-review opt-in per rule; every auto-review shows its rule                                                                                      |
| Notification noise makes agents ignore collaboration signals                                                                                                         | Real conflicts get missed                                           | Two thresholds, competition and ignore lists, AI impact filter after merge; measure notification counts in scenarios                                                                                                    |
| AI cost and latency on large diffs                                                                                                                                   | Slow or expensive grouping                                          | Deterministic passes first; AI only on what is left; per-change token budget; results cached per revision                                                                                                               |
| Cloudflare Artifacts is in beta: its API changes, it has an outage, or a plan or limit rules a deployment out (Workers Paid only, 1 GB per repo, no local simulator) | Git hosting breaks or cannot be deployed                            | All git calls go through `libs/git-host`, so a change lands in one package and the engine in [git-engine.md](./git-engine.md) can be a second backend; e2e runs against the real service so API changes surface at once |
